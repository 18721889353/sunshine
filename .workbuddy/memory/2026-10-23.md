### 重要设计取舍（已知且需留意）
- **新增包 `pkg/gocrypto/rsaes`**：Go 1.26+ 把 `rsa.EncryptPKCS1v15/DecryptPKCS1v15` 标记 Deprecated（SA1019 会报），但存量对接方（Java RSA/ECB/PKCS1Padding）必须用 PKCS#1 v1.5，故自研兼容层。
  - `Decrypt` 走 `priv.Decrypt(rand, ct, nil)` → 即标准库 `DecryptPKCS1v15`，常量时间与 FIPS 门控都在，**行为等价、安全**。
  - `Encrypt` 自实现模幂用 `big.Int.Exp`，**非常量时间**；标准库对应实现走 fips140/bigmod 是常量时间的。且 `Encrypt` 未复刻 `fips140only` 门控（FIPS-only 下仍会产出 v1.5 密文，而 Decrypt 会被标准库拦）。属"为绕开弃用告警而牺牲常量时间"的取舍，包注释里"公钥运算无保密侧信道"的说法不严谨（明文 M 才是秘密）。低风险但需知悉。

### 优化：cache_manager 轮询响应 ctx 取消（既有问题，本次关闭）
- 背景：未拿到分布式锁时"轮询等别的实例回填缓存"的 4 处循环原先用 `time.Sleep` + 固定 5s deadline，**不响应调用方 ctx 取消**——调用方提前 cancel 仍会最多空跑 5s（旧 `executeConditionSingleflight` 还把 `ctx` 当 `_` 丢弃）。属既存小注记，本次一并优化掉。
- 改动（`pkg/common/dao/cache_manager.go`）：
  1. `waitForCachePoll(_ context.Context, ...)` → `waitForCachePoll(ctx, ...)`，循环改为 `select { case <-ctx.Done(): return nil,false; case <-timer.C: ... }`，用 `time.NewTimer`+`Reset` 复用定时器（避免 `time.After` 泄漏）。
  2. 三处内联轮询（`fetchConditionIDsFromDB` 标签 `pollIDs`、`getCount` 标签 `pollCount`、`getExists` 标签 `pollExists`）同样改为 `select` 监听 `ctx.Done()`，取消即 `break` 落到后续 DB 查询（DB 通常会因 ctx 快速失败）。
- 语义保持：超时/取消都走到"DB fallback"分支，与改动前超时行为一致；唯一差异是取消后**不再最多空跑 5s**。
- 验证：`gofmt -w` 后 `go build ./...`/`go vet ./pkg/common/dao/...`/`golangci-lint run ./pkg/common/dao/...` 均 0 问题；`pkg/common/dao` 无基础设施依赖的单测 `ok`。`timer.Reset` 前已在 select 中排空 `timer.C`，无 use-after-fire 风险。
