📦一、前置准备

1.1 环境要求清单

项目 要求 说明
代码仓库 Gitee 账号 + 仓库 已推送 fuliApiGo 代码
阿里云账号 实名认证 访问 cloud.aliyun.com
ECS 服务器 Linux (CentOS/Ubuntu) IP: 47.94.95.162 (示例)
Go 版本 Go 1.25+ 项目 go.mod 指定
Make工具 已安装 make 用于执行构建命令

1.2 检查清单

  • 代码已推送到 Gitee 仓库
  • Makefile 中存在 make build 命令

  • ECS 安全组开放必要端口 (8282, 8283)
确保你的项目根目录包含 Makefile,且 make build 命令可以成功编译出 Linux 二进制文件。

建议使用 develop 分支进行开发部署,main 分支用于生产环境。

☁️三、阿里云账号准备

3.1 开通云效服务

  1. 访问 https://flow.aliyun.com/
  2. 使用阿里云账号登录
  3. 如果是首次使用,点击"立即开通"
  4. 同意服务协议,完成开通

3.2 创建企业(如果还没有)

  1. 登录后,点击右上角"创建企业"
  2. 填写企业名称: 例如 "我的开发团队"
  3. 选择行业类型
  4. 点击"确定"创建
开通成功后,你会看到云效的主控制台界面,左侧有"流水线"、"代码库"等菜单。

🏗️四、创建云效流水线

4.1 新建流水线

  1. 在云效控制台,点击左侧菜单 "流水线"
  2. 点击右上角蓝色按钮 "+ 新建流水线"
  3. 在弹出的窗口中,选择 "空白流水线" (推荐,更灵活)
  4. 输入流水线名称: fuliApiGo-CI-CD
  5. 输入描述: "从 Gitee 拉取代码,编译后部署到 ECS"
  6. 点击 "下一步"
📝 选择模板
空白流水线
📛 命名
fuliApiGo-CI-CD
➕ 添加阶段

🔧五、配置代码源(Gitee)

5.1 添加代码源

  1. 在流水线编辑页面,找到 "代码源" 区域
  2. 点击 "+ 添加代码源"
  3. 在弹出的对话框中,选择 "Gitee"
  4. 如果是首次使用 Gitee,需要授权:
    • 点击"前往授权"
    • 跳转到 Gitee 登录页面
    • 输入 Gitee 账号密码
    • 点击"授权",允许云效访问你的仓库
    • 授权成功后自动返回云效

5.2 选择仓库和分支

  1. 授权后,在下拉列表中选择你的仓库: your-username/fuliApiGo
  2. 选择分支:
    • 开发环境: develop
    • 生产环境: main
  3. 点击 "确定"
如果找不到你的仓库,请确认:
  • Gitee 账号是否正确
  • 仓库是否存在且你有访问权限
  • 是否需要重新授权

🔨六、配置构建阶段

6.1 添加 Go 构建任务

  1. 在流水线编辑页面,点击 "+ 添加阶段"
  2. 选择阶段类型: "构建"
  3. 在任务列表中搜索 "Go"
  4. 选择 "Go 构建" 任务
  5. 点击 "添加"

6.2 配置 Go 构建参数

添加任务后,会弹出配置窗口,按以下步骤填写:

基础配置:

配置项 值 说明
任务名称 Go编译构建 自定义,便于识别
Go 版本 1.25 与项目 go.mod 一致
工作目录 ./ 项目根目录

构建命令配置:

# 在"构建命令"输入框中填写: make build # 这会执行 Makefile 中的 build 目标: # cd cmd/fuliApiGo && CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -pgo=default.pgo

制品上传配置:

配置项 值
勾选"上传构建产物" ✅ 是
制品路径 cmd/fuliApiGo/fuliApiGo
制品名称 fuliApiGo-binary

6.3 (可选)添加单元测试

如果需要运行测试,可以再添加一个任务:

  1. 再次点击 "+ 添加任务"
  2. 选择 "Go 构建"
  3. 配置如下:
    • 任务名称: 运行单元测试
    • 构建命令: make test
    • 不勾选"上传构建产物"
构建成功后,二进制文件会自动上传到云效的制品库,供后续部署阶段使用。

🚀七、配置部署阶段(ECS)

7.1 添加主机部署任务

  1. 点击 "+ 添加阶段"
  2. 选择阶段类型: "部署"
  3. 在任务列表中搜索 "主机"
  4. 选择 "主机部署" 任务
  5. 点击 "添加"

7.2 配置部署主机组

第一步: 创建主机组

  1. 在"部署分组"下拉框,点击 "新建主机组"
  2. 填写主机组信息:
    • 主机组名称: fuliApiGo-Production
    • 操作系统: Linux
  3. 点击 "确定"

第二步: 添加 ECS 主机

  1. 在新建的主机组中,点击 "+ 添加主机"
  2. 填写 ECS 服务器信息:
    主机名称 fuliApiGo-ECS-01
    IP 地址 47.94.95.162
    SSH 端口 22
    用户名 root (或 ecs-user)
    认证方式 密码 或 SSH密钥
  3. 如果使用密码认证:
    • 点击"凭据管理" → "新建凭据"
    • 类型: 密码
    • 名称: ecs-root-password
    • 值: 输入你的 ECS root 密码
    • 点击"确定"保存
    • 返回选择刚才创建的凭据
  4. 点击 "测试连接",确保可以 SSH 登录
  5. 连接成功后,点击 "确定"

7.3 编写部署脚本

在"部署脚本"配置区域,选择 "在线编辑",然后粘贴以下脚本:

#!/bin/bash set -e echo "==========================================" echo " 开始部署 fuliApiGo" echo " 时间: $(date '+%Y-%m-%d %H:%M:%S')" echo "==========================================" # 1. 停止旧服务 echo "" echo "[1/6] 停止旧服务..." if pgrep -f "fuliApiGo" > /dev/null; then pkill -f "fuliApiGo" sleep 3 echo "✅ 旧服务已停止" else echo "ℹ️ 没有运行中的服务" fi # 2. 备份旧版本 echo "" echo "[2/6] 备份旧版本..." BACKUP_DIR="/opt/fuliApiGo/backup/$(date +%Y%m%d_%H%M%S)" mkdir -p $BACKUP_DIR if [ -f "/opt/fuliApiGo/fuliApiGo" ]; then cp /opt/fuliApiGo/fuliApiGo $BACKUP_DIR/ echo "✅ 二进制文件已备份到: $BACKUP_DIR" fi if [ -d "/opt/fuliApiGo/configs" ]; then cp -r /opt/fuliApiGo/configs $BACKUP_DIR/ echo "✅ 配置文件已备份" fi # 3. 创建部署目录 echo "" echo "[3/6] 创建部署目录..." mkdir -p /opt/fuliApiGo/configs mkdir -p /opt/fuliApiGo/logs echo "✅ 目录创建完成" # 4. 部署新二进制文件 echo "" echo "[4/6] 部署新版本..." # 云效会将制品下载到当前工作目录 if [ -f "fuliApiGo" ]; then cp fuliApiGo /opt/fuliApiGo/fuliApiGo chmod +x /opt/fuliApiGo/fuliApiGo echo "✅ 二进制文件部署成功" else echo "❌ 错误: 找不到 fuliApiGo 二进制文件" exit 1 fi # 5. 检查配置文件 echo "" echo "[5/6] 检查配置文件..." if [ ! -f "/opt/fuliApiGo/configs/fuliApiGo.yml" ]; then echo "❌ 错误: 配置文件不存在!" echo "请手动上传配置文件到: /opt/fuliApiGo/configs/fuliApiGo.yml" echo "可以使用命令: scp configs/fuliApiGo.yml root@47.94.95.162:/opt/fuliApiGo/configs/" exit 1 else echo "✅ 配置文件存在" fi # 6. 启动服务 echo "" echo "[6/6] 启动服务..." cd /opt/fuliApiGo nohup ./fuliApiGo -c configs/fuliApiGo.yml > logs/app.log 2>&1 & APP_PID=$! echo "进程 PID: $APP_PID" # 等待服务启动 sleep 5 # 验证服务是否启动成功 if pgrep -f "fuliApiGo" > /dev/null; then echo "" echo "==========================================" echo " ✅ 部署成功!" echo "==========================================" echo "进程ID: $(pgrep -f fuliApiGo)" echo "日志文件: /opt/fuliApiGo/logs/app.log" echo "查看实时日志: tail -f /opt/fuliApiGo/logs/app.log" echo "" echo "服务地址:" echo " - HTTP: http://47.94.95.162:8282" echo " - gRPC: 47.94.95.162:8283" else echo "" echo "==========================================" echo " ❌ 服务启动失败!" echo "==========================================" echo "最后 50 行日志:" tail -n 50 /opt/fuliApiGo/logs/app.log exit 1 fi

脚本配置说明:

执行用户 root
执行目录 /opt/fuliApiGo
超时时间 300 秒
重要: 首次部署前,需要手动上传配置文件到 ECS:
scp D:\go\src\fuliApiGo\configs\fuliApiGo.yml root@47.94.95.162:/opt/fuliApiGo/configs/

⚡八、配置触发器

8.1 添加代码提交触发器

  1. 在流水线编辑页面,点击左侧菜单 "触发器"
  2. 点击 "+ 添加触发器"
  3. 选择触发类型: "代码提交触发"
  4. 配置触发规则:
    触发事件 Push
    分支过滤 develop (或 main)
    启用触发器 ✅ 开启

配置触发器后,每次向指定分支推送代码,都会自动触发流水线执行,实现持续集成和部署(CI/CD)。

8.2 (可选)添加定时触发器

如果需要定期部署,可以添加定时触发:

  1. 添加触发器,选择 "定时触发"
  2. 配置 Cron 表达式,例如:
    • 每天凌晨 2 点: 0 2 * * *
    • 每小时: 0 * * * *

🔍十、常见问题排查

10.1 构建失败 - 找不到依赖

现象: 编译时报错 "package xxx not found"

原因: go.mod 或 go.sum 未提交到 Git

解决:

# 在本地执行 git add go.mod go.sum git commit -m "fix: add go.mod and go.sum" git push origin develop

10.2 部署失败 - SSH 连接超时

现象: 部署阶段报错 "Connection timeout"

原因: ECS 安全组未开放 22 端口

解决:

  1. 登录阿里云控制台 → ECS → 实例
  2. 找到你的 ECS,点击"更多" → "网络和安全组" → "安全组配置"
  3. 添加入方向规则:
    • 端口范围: 22/22
    • 授权对象: 0.0.0.0/0 (或云效的 IP 段)
    • 优先级: 1

10.3 服务启动失败 - 端口被占用

现象: 日志显示 "address already in use"

解决:

# 查找占用端口的进程 lsof -i :8282 # 或 netstat -tlnp | grep 8282 # 杀死进程 kill -9 # 重新启动服务 cd /opt/fuliApiGo nohup ./fuliApiGo -c configs/fuliApiGo.yml > logs/app.log 2>&1 &

10.4 配置文件不存在

现象: 部署脚本报错 "配置文件不存在"

解决: 首次部署需要手动上传配置文件

# 从本地上传 scp D:\go\src\fuliApiGo\configs\fuliApiGo.yml root@47.94.95.162:/opt/fuliApiGo/configs/ # 或者在 ECS 上直接创建 ssh root@47.94.95.162 mkdir -p /opt/fuliApiGo/configs vi /opt/fuliApiGo/configs/fuliApiGo.yml # 粘贴配置内容并保存

10.5 数据库连接失败

现象: 服务启动后日志显示数据库连接错误

检查:

  1. 确认数据库中白名单已添加 ECS 的公网 IP
  2. 检查配置文件中的数据库地址、用户名、密码是否正确
  3. 测试数据库连接:
    mysql -h your-db-host -u username -p

10.6 Gitee 授权失败

现象: 无法选择 Gitee 仓库

解决:

  1. 检查 Gitee 账号是否正确
  2. 尝试取消授权后重新授权
  3. 确认仓库存在且有访问权限
  4. 如果是私有仓库,确认已添加云效为协作者

⭐十一、最佳实践

11.1 多环境部署策略

建议创建多条流水线,对应不同环境:

流水线名称 触发分支 部署目标 触发方式
fuliApiGo-Dev develop 开发环境 ECS 自动触发
fuliApiGo-Staging release/* 测试环境 ECS 手动触发
fuliApiGo-Prod main 生产环境 ECS 手动触发 + 审批

11.2 添加人工审批节点

生产环境部署前,建议添加审批环节:

  1. 在部署阶段前,添加 "人工卡点" 任务
  2. 配置审批人: 项目负责人
  3. 设置审批超时时间: 24 小时
  4. 只有审批通过后,才会执行部署

11.3 健康检查

在部署脚本最后添加健康检查:

# 等待服务完全启动 sleep 10 # 健康检查 MAX_RETRIES=5 RETRY_COUNT=0 while [ $RETRY_COUNT -lt $MAX_RETRIES ]; do if curl -f http://localhost:8282/health > /dev/null 2>&1; then echo "✅ 健康检查通过" break else RETRY_COUNT=$((RETRY_COUNT + 1)) echo "健康检查失败,第 $RETRY_COUNT 次重试..." sleep 5 fi done if [ $RETRY_COUNT -eq $MAX_RETRIES ]; then echo "❌ 健康检查失败,服务可能未正常启动" exit 1 fi

11.4 快速回滚方案

保留最近 5 个版本的备份,支持快速回滚:

#!/bin/bash # rollback.sh - 快速回滚脚本 echo "可用的备份版本:" ls -lt /opt/fuliApiGo/backup/ | head -6 read -p "请输入要回滚的备份目录名: " BACKUP_NAME BACKUP_PATH="/opt/fuliApiGo/backup/$BACKUP_NAME" if [ ! -d "$BACKUP_PATH" ]; then echo "错误: 备份目录不存在" exit 1 fi # 停止当前服务 pkill -f fuliApiGo sleep 3 # 恢复备份 cp $BACKUP_PATH/fuliApiGo /opt/fuliApiGo/fuliApiGo chmod +x /opt/fuliApiGo/fuliApiGo # 启动服务 cd /opt/fuliApiGo nohup ./fuliApiGo -c configs/fuliApiGo.yml > logs/app.log 2>&1 & echo "✅ 回滚完成"

11.5 日志管理

配置日志轮转,避免日志文件过大:

# 创建 logrotate 配置 sudo vi /etc/logrotate.d/fuliApiGo # 添加以下内容: /opt/fuliApiGo/logs/*.log { daily rotate 7 compress delaycompress missingok notifempty create 0644 root root postrotate # 如果需要,可以发送信号让应用重新打开日志文件 endscript }

11.6 监控告警

建议配置以下监控:

  • 进程监控: 使用 systemd 或 supervisor 管理进程
  • 端口监控: 监控 8282、8283 端口是否监听
  • 资源监控: CPU、内存、磁盘使用率
  • 日志监控: 接入阿里云 SLS 日志服务
  • 链路追踪: 已配置 Jaeger 链路追踪
进阶建议:
  • 使用 Docker 容器化部署,提高环境一致性
  • 接入 Prometheus + Grafana 监控体系
  • 配置自动化测试,确保代码质量
  • 使用蓝绿部署或滚动发布,减少停机时间
